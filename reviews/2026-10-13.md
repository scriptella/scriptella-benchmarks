# Review — 2026-10-13

## Scriptella CSV formatting and MariaDB timings

The benchmark-specific `Format` subclasses were non-idiomatic: Scriptella's
CSV driver already supports declarative parsing with built-in `number` and
`timestamp` types. Benchmark v3 removes those custom formatter classes and
uses `format.<column>.type` rules, simplifying the ETL configuration. This is
not evidence of a performance improvement. This path passes parsed `Number` values to JDBC,
whereas the handwritten JDBC baseline binds amounts as `BigDecimal`; they are
different conversion paths. The full-run verifier now checks representative
fractional amounts in both PostgreSQL and MariaDB.

## Targeted local batch-1,000 observations

One targeted local run measured the Scriptella built-in formatter setup and
the handwritten JDBC baseline for the 1,000,000-row fixture:

| Database | Scriptella | JDBC |
|---|---:|---:|
| PostgreSQL | 15.067 s | 11.346 s |
| MariaDB | 8.551 s | 5.485 s |

These are single-run observations, not medians or official v3 results. The raw
run metadata identifies the benchmark as `v2`; that provenance is preserved.
The measured Scriptella configuration uses the built-in number and timestamp
format rules introduced for v3, while the raw metadata was created before the
version identifier was updated. The full GitHub Actions run will provide the
official v3 measurements. Historical v2 results remain unchanged.

## MariaDB import with all format rules removed

As an exploratory comparison, removing all per-column `format.*` settings
improved the measured Scriptella import times for the 1,000,000-row fixture:

| Mode | Without formatters | Previous v2 median | Change |
|---|---:|---:|---:|
| Unbatched | 181.844 s | 220.081 s | 17.4% faster |
| Batch 1,000 | 6.869 s | 9.523 s | 27.9% faster |

Both no-format imports passed row-count and sample-value verification. The
previous medians are from two runs using the custom formatters; the no-format
figures are from one run on the same local environment and fixture. This
suggests formatting work may add cost, but it does not establish the cost of
the v3 built-in rules: run-to-run variation and the single sample limit the
conclusion. PostgreSQL could not use the same untyped CSV values because its
JDBC driver rejected strings for typed columns, so this no-format comparison is
MariaDB-only.
